# Timestamp fixtures

`fixtures/lake-initial.ers` and `fixtures/lake-renewed.ers` are generated by lake's production
`TimestampService` from lake `main` at commit `6d9ab8d` (the lake #36 implementation). The
generator compiles the exact lake `src/transparency/timestamps.cpp` translation unit and supplies
the same OpenSSL-backed stub-TSA shape used by lake's `TransparencyTimestamp` tests. The retained
root certificate is the only trust anchor and `checkpoint-signature.bin` is the decoded signature
value timestamped by the first token.

From this liquid worktree, with the lake checkout at the path named in issue #210, regenerate once
with:

```sh
LAKE_ROOT=/Users/stevesperandeo/dev/oramasearch/codex-work/lake
/opt/homebrew/opt/llvm/bin/clang++ -std=c++26 -fexperimental-library \
  -I"$LAKE_ROOT/include" \
  -Imodules/automerge-cpp/upstream/json/include \
  -I/opt/homebrew/opt/openssl@3/include \
  tests/transparency/generate_lake_fixture.cpp \
  "$LAKE_ROOT/src/transparency/timestamps.cpp" \
  -L/opt/homebrew/opt/openssl@3/lib -lcrypto \
  -o build/generate-lake-timestamp-fixture
./build/generate-lake-timestamp-fixture tests/transparency/fixtures
```

The generator intentionally creates fresh keys, nonces, serials, and generation times. Generated
files are reviewed and committed; normal tests never run the generator or link OpenSSL for these
verification operations.
